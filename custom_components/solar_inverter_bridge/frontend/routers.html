Router setup

Choose your router, check the addresses, and generate commands to copy. Start with DNS only; add port redirection only if needed.

Check which DNS server the inverter uses. It must send its DNS requests to the router or DNS server where you add these records. For example, records on your router will not help if the inverter asks 8.8.8.8. Set the inverter's DNS server through DHCP or its network settings, or enable DNS interception below. Reconnect the collector after changing DHCP DNS settings. Home Assistant is the address returned by DNS, not the DNS server.

1. Addresses and router

Known addresses are filled in. Check them and enter any missing values.

Advanced: interfaces and zones (optional)

Leave these empty for a typical LAN. MikroTik and Linux use IP-scoped rules without interface names. OpenWrt, pfSense, and OPNsense use their standard lan zone/interface. Change these only for a different LAN or VLAN setup.

Use fixed LAN addresses for HA and the DNS server.

2. Connection method and scope

If the domains already point to HA and ports 502/18899/38899 are reachable, port redirection is usually unnecessary. EyeBond on 502 is not a standard Modbus TCP server. Check each listener in Bridge; DNS does not change ports.

Enable this only if the inverter uses another DNS server and you cannot change it.

Shared rules match this subnet directly. Shared DNS interception also affects other clients; an external DNS resolver is bypassed to prevent a loop.

For DNS-only or shared subnet rules, a changing collector IP is less important. Bridge must still allow the new source address.

3. Collector domains

Choose the individual names you need, or enable *.eybond.com to cover them together. The wildcard starts unchecked. When selected, the individual EyeBond checkboxes below it are disabled; their choices return when you uncheck the wildcard.

The list also includes API and website domains found in ha-dessmonitor. They are not confirmed collector destinations and start unchecked. “Select all” includes every listed domain. Select them if needed for your device; rewriting API/website names to HA can interrupt access to those cloud services for clients using this DNS server.

Switching to the local bridge

  1. Configure local DNS, and only the redirection rules you need.
  2. A new TCP session is required. DNS/NAT changes do not move an established cloud connection. The most targeted option is restarting the inverter's Wi-Fi module through its vendor app, if supported. Reconnecting Wi-Fi or restarting the access point/router also breaks the old connection, but affects other devices.
  3. Cached DNS may keep the old destination until it expires or the module resolves again. After reconnecting, check for fresh complete readings in Bridge.

DHCP reservation and changing IPs

Reserve the collector's IP in the DHCP server whenever a rule matches that individual IP. Otherwise a lease change breaks the rule. Use the DHCP client list and its “make static / reserve” action; a reservation also needs the collector's MAC, so an IP alone cannot create it correctly.

With DNS-only or shared subnet rules, a fixed collector IP is less critical. Bridge identifies the collector by its native DTUPN identity, stored as a hash, rather than its IP. A new IP preserves the saved inverter, name, settings, and journal if that source still passes the allowlist. Replacing the Wi-Fi module can change its identity.

Verification and rollback

Use the generated checks to confirm the DNS answer, rule counters, and fresh readings. Local DNS overrides can affect all clients using that resolver. These recipes cover IPv4 and ordinary DNS, not IPv6 or encrypted DNS.

To roll back, remove only the SolarInverterBridge-tagged rules/overrides added by this guide, restore the previous resolver settings, and establish a new connection to the intended owner. Generated commands are configuration recipes; only the user's MikroTik DNS setup has hardware evidence here.
